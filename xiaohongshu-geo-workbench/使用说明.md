# 小红书 GEO 网页工作台

## 启动

```bash
cd ~/.xiaohongshu-geo-agent/xiaohongshu-geo-workbench
python3 server/app.py
```

Claude API Key 有两种给法，页面填写的优先：

- 在网页左栏填写。Key 只随每次请求发给本机后端，不写入任何文件；勾选“在本浏览器记住”会存在这个浏览器里。
- 启动前在终端执行 `export ANTHROPIC_API_KEY="你的 Key"`，作为页面没填时的默认 Key。

浏览器打开 http://127.0.0.1:8788 。模型默认 `claude-opus-5`，可用 `export CLAUDE_MODEL=...` 更换（例如 `claude-sonnet-5` 更便宜）。

首次使用需安装 SDK：`python3 -m pip install --user anthropic`。

## 流程与 token 消耗

| 操作 | 是否联网搜索 | 是否消耗 token |
|---|---|---|
| 搜索证据（新品牌 / 重新搜索） | 是 | 是，最贵的一步 |
| 从证据库选择已有快照 | 否 | 否 |
| 生成问题库 | 否，只用已保存的证据 | 是 |
| 质量检查 | 否 | 否，本地规则 |
| AI 实测 | 否，在各 AI 产品里手动提问 | 否，只记录回答 |

## 文件存放

- `data/evidence/<品牌>/<时间>.json`：第 1 步证据快照，同一品牌可以有多份。
- `data/runs/<品牌>/<时间>.json`：每次生成的问题库和质量检查结果，记录了用的是哪份快照。

这些都是普通 JSON 文件，可以直接备份、删除或交给别人复用。

## AI 实测

1. 在「问题库」里选好一次生成结果，切到「AI 实测」。
2. 填要测的 AI 产品（如 点点,豆包,DeepSeek）和每题重复次数，点「生成测试计划」。
3. 逐条「复制问题」，到对应产品里新开对话提问（多轮题在同一个对话里按顺序问），把回答全文贴回「记录回答」，有引用来源也一并贴上。
4. 程序自动判断回答里有没有提到品牌；是否推荐、描述是否准确、是否满足用户意图由人来选。

结果存在 `data/live/<品牌>/<时间>.json`，并同步到这次问题库的检查报告里。实测结果单独统计，不改变问题库的质量结论。
